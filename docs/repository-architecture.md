## Architecture

CareSync is a **Flutter mobile application** (Android primary, iOS secondary) backed by two separate persistence layers operating in parallel:

1. **Firebase / Cloud Firestore** — the canonical, authoritative data store for all user health data, medicines, logs, appointments, notifications, and caregiver connections. All writes go here first.
2. **Local Python/Flask backend** (`caresync_backend/`) — a SQLite-backed REST API running at `http://10.0.2.2:5000` (Android emulator localhost). This is a **secondary mirror / fallback**, not the primary store. Production app cannot reach this unless the local server is running.

### Dual-Store Strategy (CONFIRMED)

> Source: `lib/services/medicine_service.dart:22-57` and `lib/services/api_service.dart:14`

```
Primary Write → Firestore
                    ↓
    Local backend mirror (fire-and-forget, 1500ms timeout)
                    ↓
    On Firestore read failure → fallback to local backend
```

The Flutter app imports `http` for REST calls AND the Firebase SDKs. All real data flows through Firestore; local backend is used for:
- Initial prototype compatibility
- Backend sync on login (`syncUser`)
- Inventory fallback on Firestore read failure
- Chatbot (AI response) — the only feature exclusively served by the Flask backend

- Source: `api_service.dart:585-603`

- Deleted on logout: `api_service.dart:605-627`

#### Role System
- Two roles: `'patient'` and `'caregiver'`
- Stored in Firestore `users/{uid}.role`
- Auto-healed if absent (defaults to `'patient'` for users with health data)

## Prescription OCR

### CONFIRMED EVIDENCE

**Source files:** `lib/screens/scan_prescription_screen.dart`

#### Technology
- **Google ML Kit Text Recognition** (`google_mlkit_text_recognition: ^0.14.0`)
- Package: `TextRecognizer` (Latin script recognizer)

#### OCR Pipeline
1. User picks image from **camera** or **gallery** via `image_picker`
2. `InputImage.fromFile()` is created, fed to `textRecognizer.processImage()`
3. Text blocks are iterated; each `TextLine` is examined:
   - If a dosage pattern is found (`RegExp r"(\d+(\.\d+)?\s*(mg|ml|mcg|g|tabs|units))"`) → extracted as `{name, dosage}`
   - If no dosage but ≤3 words and no digits → treated as a medicine name
4. Results are capped at **10 detected medicines**
5. User reviews, edits (name, dosage, frequency), removes, or adds manually
6. Each medicine can be individually customized via `AddMedicineScreen` with full schedule setup
7. "Confirm & Save All" does a duplicate check (case-insensitive name match) and calls `MedicineService.addMedicine()` for each non-duplicate

#### Disclaimer
The screen displays: _"Please verify medicines with your doctor. OCR detection is provided for convenience and must be reviewed."_

#### Limitations (CONFIRMED from code)
- OCR is purely **local**, no cloud vision API
- Frequency is set to "Once Daily" by default
- Default stock set to 20 for all scanned medicines
- No AI/LLM involved in parsing — pure regex

#### Firestore Security Rules Summary
- Source: `firestore.rules`
- Patient has **full read/write** to own `users/{uid}` subtree

- The `isConnectedCaregiver()` function checks both orderings of `{caregiverId}_{patientId}`

## Business Logic

### CONFIRMED EVIDENCE

#### Medicine Adherence
- Adherence = `(taken_doses / total_logged_doses) * 100`
- Only `status == 'taken'` logs count
- Manual stock deductions (`deductStock`) **do not** create dose logs — they do not affect adherence
- If no logs exist but inventory is non-empty, adherence defaults to 100%
- Source: `medicine_service.dart:571-594`

#### Dose Take / Undo Cycle
- Taking a dose: creates a log doc in `medicine_logs`, decrements `total_stock` by 1
- Undo dose: **duplicate protection** — verifies log exists before deleting; restores stock +1
- Undo protection key: `{medicine_name.toLowerCase()}_{reminder_time}` in today's logs
- Source: `medicine_service.dart:245-392`

#### Notification Timing
